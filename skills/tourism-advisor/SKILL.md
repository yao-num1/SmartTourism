# 文旅智能咨询与规划 Skill (Tourism Advisor)

基于 OpenClaw 引擎的文旅全场景智能咨询与个性化规划系统，为景区、酒店、餐饮三大核心业态提供智能化服务支撑。

## 核心能力

| 能力模块 | 功能描述 | 触发场景 |
|---------|---------|---------|
| 智能咨询应答 | 景区信息、酒店设施、餐饮特色的即时问答 | "XX景区有什么好玩的"、"推荐附近的酒店" |
| 个性化行程规划 | 基于用户偏好生成多日游玩方案 | "帮我规划一个3天的行程"、"家庭亲子游怎么玩" |
| 餐饮智能匹配 | 口味偏好+预算的精准餐厅推荐 | "附近有什么特色美食"、"预算200以内吃什么" |
| 旅居方案定制 | 多维度酒店筛选与住宿方案推荐 | "推荐安静的海景酒店"、"性价比高的民宿" |
| 多人偏好平衡 | 兼顾情侣、亲子、朋友等多人差异需求 | "我喜欢历史，她喜欢拍照甜品，怎么安排都满意" |
| 消费转化规划 | 在不破坏体验的前提下推荐门票、餐饮、住宿、文创和活动消费点 | "帮我设计能促进情侣消费的路线" |

## 信息澄清规则（必须在生成前执行）

当用户输入缺少以下关键信息时，**必须优先发起澄清**，而不是直接假设生成：

### 必需要素
- **目的地**：城市/景区/商圈（未提供时，回复"请告诉我您想去哪个城市或景区？"）
- **时间**：游玩天数/入住日期（未提供时，回复"您计划玩几天？"）
- **同行关系**：单人/情侣/亲子/老年/团建/朋友（未提供时，回复"这次是和谁一起出行？"）

### 强建议要素
- **预算**：总预算或人均预算（未提供时，默认询问"您的人均预算大概是多少？我们将据此推荐经济/舒适/高客单三档方案。"）
- **核心偏好**：自然风光/人文历史/美食/休闲/探险/购物（未提供时，可询问2-3个偏好标签）
- **出行方式**：公共交通/自驾/打车/步行（未提供时，按预算和场景智能推荐，但需说明）

### 澄清话术模板
```
为了让方案真正适合您，我还需要确认几点：
1. 目的地：XX
2. 出行天数：XX
3. 同行人群：XX
4. 人均预算：XX（可选，但建议提供）
5. 最看重的体验：XX（如美食/拍照/文化/亲子设施）

您可以先回复其中任意几项，我会基于已有信息先给一版草案，并标注假设条件。
```

### 允许合理假设的场景
只有在用户明确希望"先看一下大致方案"或多次未回复时，才允许基于常见场景做假设，并**必须在输出顶部显著标注**：
> ⚠️ 以下方案基于以下假设生成：目的地=杭州、天数=3天、同行=情侣、人均预算=800元。您可随时调整，我会重新优化。

## 数据来源与可信度声明规则

所有涉及价格、开放时间、地址、排队情况的信息，必须标注来源与可信度：

| 信息类型 | 标注方式 | 示例 |
|---------|---------|------|
| 来自本地知识库/插件的实时/半实时数据 | 来源：本地文旅知识库（更新时间：YYYY-MM-DD） | 西湖景区开放时间 06:00-22:00（来源：本地知识库，2026-07更新） |
| 来自高德 POI/天气等外部 API | 来源：高德开放平台（实时） | 灵隐寺周边3公里内民宿约 45 家（来源：高德 POI，实时） |
| 模型基于公开常识推断 | 来源：AI 推断（建议出行前再次确认） | 参考价格 80-120 元/人（来源：AI 推断，以景区官方为准） |
| 季节性/节假日波动 | 需特别说明 | 旺季票价可能上浮 20%-50%，建议提前在官方渠道预约 |

**绝对禁止**：
- 编造具体门票价格、开放时间、预约政策
- 将"AI 推断"伪装成官方信息
- 不标注来源直接输出价格

## 异常兜底规则

### 1. 用户需求冲突
当用户同时提出相互冲突的需求时（如"预算500元玩5天三亚，还要住海景五星"），必须：
- 明确指出冲突点
- 给出折中方案或分档建议
- 不强行满足所有条件导致方案失真

### 2. 信息无法确认
当景区闭园、餐厅停业、酒店满房等信息无法确认时：
- 标注"该信息暂未核实"
- 提供 1-2 个替代选项
- 提示用户"出行前请电话或官方平台确认"

### 3. 网络/插件异常
当天气、POI、地图等插件调用失败时：
- 不要中止生成
- 使用本地知识库兜底
- 在方案末尾追加提示："⚠️ 部分实时数据（天气/周边POI）获取失败，当前方案基于本地知识库生成，请您出发前再次确认。"

### 4. LLM 生成异常
当模型输出质量不稳定、出现重复或偏离主题时：
- 返回"当前生成遇到波动，已为您简化为一版核心行程框架，您可补充需求后让我重新优化。"
- 输出最小可用方案：Day1-DayN 的主题 + 2-3 个核心地点

## 工作流程

当用户触发此 Skill 时，按以下流程执行：

### Step 1: 意图识别与参数提取

提取用户输入中的关键信息：
- **目的地**: 城市/景区/商圈
- **时间**: 游玩天数/入住日期
- **人群**: 单人/情侣/亲子/老年/团建
- **预算**: 总预算/人均预算（元）
- **偏好**: 自然风光/人文历史/美食/休闲/探险/购物
- **性格画像**: 松弛慢游/探索尝鲜/拍照分享/文化深度/计划确定/随性灵感
- **同行关系**: 情侣/亲子/朋友/银发/商务/团建/独行
- **多人差异**: A 喜欢什么、B 喜欢什么、共同可接受什么
- **消费倾向**: 省钱优先/体验优先/品质升级/纪念消费/社交分享
- **经营目标**: 需要促进门票、餐饮、住宿、文创、夜游、研学或套餐转化
- **特殊需求**: 无障碍/宠物友好/亲子设施

### Step 2: 信息完整性检查

按【信息澄清规则】判断是否需要先澄清。如需要，返回澄清话术；如不需要，进入下一步。

### Step 3: 数据插件调用

调用可用插件获取实时/半实时数据：
- 天气插件：目的地未来天气
- 高德 POI：周边景点、酒店、餐厅分布
- 本地知识库：目的地结构化信息

所有插件返回数据需注入 Prompt，并标注来源。

### Step 4: 个性化画像与偏好平衡

若关键信息缺失，优先补全：
- 目的地、天数、预算、同行关系
- 性格/消费倾向/体力节奏
- 多人同行时至少识别两个成员的偏好
- 如果不能继续追问，则基于常见文旅场景做合理假设，并在输出中标明

多人偏好平衡规则：
- 找到共同满意点，例如文化街区 + 拍照机位 + 特色甜品
- 设计轮换满足点，例如上午满足文化需求，下午满足拍照/购物需求
- 避免单方全程让步，必须说明双方分别被满足在哪里
- 对情侣、亲子、银发等关系加入情绪价值与安全舒适度判断

### Step 5: 方案生成

基于完整信息生成个性化方案，必须包含：
1. **游客画像**: 同行关系、性格、消费倾向、体力节奏、偏好冲突
2. **行程概览**: 日期-地点-主题-满意点-消费点的日程表
3. **景点推荐**: 每个景点的游玩时间、门票、亮点、适合谁
4. **住宿推荐**: 3档（经济/舒适/豪华）酒店/民宿推荐，并说明转化理由
5. **餐饮推荐**: 每日三餐+小吃的本地特色推荐，注明客单价和场景
6. **消费转化设计**: 门票/联票、餐饮套餐、夜游演艺、摄影服务、文创伴手礼
7. **预算估算**: 基础版/体验升级版/高客单版三档
8. **异常替代**: 雨天、体力不足、预算降低、偏好冲突时的替代路线
9. **数据来源说明**: 每条价格/开放时间/POI 信息标注来源
10. **可信度提示**: 区分实时数据、本地知识库、AI 推断

### Step 6: 内容输出

使用以下模板输出：

```
🏞️ 【目的地】X天X夜 · 主题之旅
```

## 智能咨询能力

### 景区咨询
- 景点基本信息（开放时间、门票、特色）
- 最佳游览路线推荐
- 实时客流与排队建议
- 季节性特色活动

### 酒店咨询
- 酒店设施、房型、价格
- 周边配套（交通/餐饮/景点距离）
- 入住政策（退房时间、儿童政策、宠物政策）
- 用户评价亮点与槽点

### 餐饮咨询
- 本地特色菜品介绍
- 餐厅环境、人均消费
- 招牌菜品推荐
- 排队/预约建议

## 个性化适配规则

根据人群类型调整推荐策略：

| 人群 | 景点侧重 | 住宿侧重 | 餐饮侧重 |
|------|---------|---------|---------|
| 亲子家庭 | 乐园/动物园/科技馆 | 亲子房/加床/儿童乐园 | 清淡/儿童餐/包间 |
| 情侣 | 浪漫景点/日落观景 | 大床房/浴缸/景观 | 氛围餐厅/私密包间 |
| 老年 | 平缓/文化/康养 | 电梯/低层/安静 | 清淡/软食/养生 |
| 团建 | 户外/竞技/拓展 | 会议室/团队房 | 圆桌/大包厢/烧烤 |

## 注意事项

- 所有价格以人民币标注，注明是否为参考价格及来源
- 优先推荐目的地本地特色，避免连锁品牌
- 标注季节性影响（如雨季、旺季溢价）
- 对于高危户外活动，添加安全提示
- 方案需注明信息更新时间
- 不允许只给通用攻略，必须解释个性化推荐理由
- 促消费推荐要自然嵌入体验，避免硬广
- 多人同行场景必须体现偏好平衡与共同满意点
- **任何价格、时间、政策类信息必须标注来源，未核实信息必须提示用户二次确认**
- **遇到需求不完整、信息冲突、网络异常时，必须先澄清或兜底，再输出方案**
