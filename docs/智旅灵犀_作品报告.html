第 1 章　摘要

本报告给出「智旅灵犀」文旅全场景智能辅助系统（v2.2.0）的设计与实现。系统针对文旅行业景区、酒店、餐饮核心业态中的 消费体验同质化、客源转化效率低、产品创新迭代慢三大痛点，以 Flask + waitress 后端 + 无框架单页前端 + 国产大模型 API 的组合， 通过轻量化智能 Skill 协同实现智能咨询应答、个性化行程规划、营销内容生成、文创产品赋能与客源精准匹配五大核心场景； 并以「画像驱动的行程规划」与「营销素材生成 + 文创数字名片」为两条主线，不做功能堆叠。

第 2 章　项目背景与痛点分析

文旅景区、酒店、餐饮三大核心业态长期面临结构性困境。消费体验同质化：网络攻略与行程模板千人一面，难以适配同行人群、节奏与预算差异； 客源转化效率低：营销素材依赖人工撰写，线下文创包装印死图文，实物无法承担获客职能； 产品创新迭代慢：从社交平台热点出现到形成可售的产品创意，传统流程以周计，热点红利窗口往往已经关闭。

行业现有单点工具多为「通用对话 + 固定模板」，AI 未承担核心业务任务。本项目以「智能适配、创新迭代、精准创收」为目标， 把传统「人工服务、固化产品、被动经营」的运营模式重构为数据与模型驱动的新模式，痛点量化与对策见表 2-1。

三大痛点不是并列的三件事，而是一条因果链：体验同质化使游客缺少非来不可的理由，转化效率低使商家看不到门票之外的收益， 产品迭代慢使文化资源停在展示层。系统因此不做三个各管一头的独立小工具，而是用同一套画像与数据底座承接三者—— 画像驱动行程对应同质化，营销素材与数字名片对应转化，热点灵感库与文创生成对应迭代速度。 AI 是否真正承担了业务任务的判准也在此定下：产出必须落到可执行的对象上（一条能导航的路线、一张能印刷的名片、 一个能点开的购票深链），而不只是一段读起来通顺的文字。

第 5 章　核心功能实现①：个性化行程规划

行程规划（链路见图 4-1）的要点是规则先行、模型成文、数据可溯：缺参先澄清、不臆造不瞎编；plan_generator 按规则产出每日主题、消费点与预算框架； 注入天气、高德 POI、美团票价等实时数据后交由模型按固定模块成文（输出经 clean_llm_output 规整），最后标注来源并双层渲染。 输出包含十一个模块（图 5-1），「思考与依据」折叠层置于开头，浏览层按一至五重新编号。

7.2 三道闸口与「降级不静默」

  • 第一道 · 输入闸口：必填三要素缺失即返回澄清话术，先于任何生成（见表 5-1）。
  • 第二道 · 数据闸口：价格 / 图片 / 开放时间只认实时接口与库内真实数据，缺失走 image_missing 与「暂未核实」。
  • 第三道 · 输出闸口：模型输出经 validation 校验（绝对化用语、无来源价格、编造图片链接），问题以 SSE 事件如实下发。

三道闸口不合并成一道，是因为它们挡住的是三种来源不同的错误：输入闸口挡用户的省略，数据闸口挡上游的缺失， 输出闸口挡模型的编造；三者的处置手段也因此不同——前者追问、中者占位、后者告警。 输出闸口刻意只做校验与如实下发，不自动改写文本：在没有真值可对照时，把一句正常表述改成同义说法既可能改错， 也剥夺了用户自己判断的机会，所以问题回给前端与面板，改不改由人决定。

校验环节本身也可能出错，因此它降级不静默：按环节兜住、计数聚合进面板 validation （runs / issues / degraded_runs / by_stage / last_error），运维面板能看到「哪一环掉过几次」， 而不是把降级吞成一次正常通过。回归：server/test_validation_degrade.py 42 项。

营销场景命中为 0，这不是异常而是机制：上游要先见过这段前缀才会命中，新前缀的第一次调用命中必为 0。 营销是一段独立 prompt 且只调一次，所以它拿不到命中 —— 报告里把它如实留成 0，比抹掉这一行更有说服力。

14.2 命中从哪来：把每次都会变的值排到提示词末尾

DeepSeek 的上下文缓存按请求前缀命中，命中价远低于未命中价。本项目因此做了一次提示词前缀稳定化改造： 把分钟级时钟、IP 定位、Skill 正文这类每轮都变的值一律移到末尾，头部逐字不动。于是同一次提问里的两次调用共用这段头部， 同会话第二轮又共用上一轮的全部内容 —— 命中 token 随轮次上升。这不是推断：改造前后各跑一遍脚本， prompt_cache_hit_tokens 从 0 变成非 0，且该数值同时进了运维面板。

14.3 只报 token，不报钱：单价走环境变量

本次测量未配置单价，因此只报 token 不报金额 —— 接口返回里写着「未配置单价…所以只报 token 不报钱」， llm_usage.cost 为空。这是刻意的设计：模型厂商在 2026 年有过调价， 任何写死在文档里的价签都会过期，所以单价只留方法、不留数字，也不写进代码。

第 16 章　已知限制与未来展望

限制逐条诚实披露，并区分三种状态：已修复 改动已合入且回归通过、 未修复 已定位仍在、保持 属外部条件或产品决策，如实说明不掩盖。

把限制写进正文而不是删掉，是成本更低的选择：被追问一条已写明的限制，代价是一句话；被追问一条没写的， 代价是整份报告的可信度。所以每条限制都带状态与出处，已修复的附回归项，未修复的写明定位到的文件与行号， 属外部条件的（账户欠费、第三方城市覆盖）不伪装成代码问题。

结语

综上，智旅灵犀以 4 个核心依赖的轻量架构，把「画像驱动的行程规划」与「印码即媒介的数字名片」两条主线做深做透； 以四级数据来源与三道反幻觉闸口保证结果可信，以全链路降级保证系统可用，以运维面板把成本、命中率与未接线模块如实摊开。 本报告的全部数字都出自源码统计、真实接口与自动化测试，可核验、可复现，也可被推翻 —— 凡做不到或未验证的，宁可留一条限制，也不写进结论。

这个项目更想被看见的不是功能数量，而是它处理「说得出」与「证得了」之间距离的方式：能测的都测并留下命令， 测不了的标明性质并留下缺口，做了一半的如实分成已接线与未接线。下一步的工作因此不是再加几个模块， 而是把第 16 章里那几条「未修复」与「保持」逐条收掉。
